# Maestro 桌面壁纸打包方案

## 目标

把当前 Maestro（FastAPI 后端 + 单文件前端 + 全量素材）打包成 Windows 桌面应用，双击 `Maestro.exe` 即起双窗口：

1. **背景壁纸层**：透明全屏 HTML，渲染 wallpaper 素材的芙莉莲 1:1 场景，不可交互（用户点桌面图标照常生效，桌宠/输入只属于下面的窗口）。
2. **交互主窗口**：PyWebView 嵌出的 Chrome 窗口，展示聊天框/工作流/任务进度卡片/桌宠，可拖、可缩、可关（关则服务退到后台）。

## 技术选型（已确认）

- **打包工具**：PyInstaller（成熟生态、hook 现成）
- **浏览器壳**：PyWebView（系统 Chromium / Edge 内核，零额外下载）
- **桌面集成**：Win32 `SetParent` 把 HTML 层挂到 `Program Manager`（WorkerW 层级，不抢焦点）
- **打包范围**：web/ + wallpaper/ + configs/ + src/ 全部进 exe（仅裁 `.bak` / `_test` / `outputs/` / `generated-images/` / `.workbuddy/`，与 `.dockerignore` 对齐）

## 实现步骤（按依赖关系排序）

### 第 1 步：环境变量定位 + PyInstaller 兼容层

新增 `src/maestro/runtime.py`，**唯一职责是把所有 `Path(__file__).parents[N]` 解析统一改写**：

```python
def project_root() -> Path:
    """打包后从环境变量/MEIPASS 解析项目根；源码运行时从 src/maestro 回溯到 repo 根。"""
    if env := os.environ.get("MAESTRO_HOME"):
        return Path(env)
    if getattr(sys, "frozen", False):  # PyInstaller onefile/onedir
        return Path(sys.executable).resolve().parent
    # 源码运行：从 src/maestro/runtime.py 回溯两级
    return Path(__file__).resolve().parents[2]
```

接着逐文件把硬编码 `Path(__file__).resolve().parents[N]` 改成调用 `runtime.project_root()`（涉及 `config.py:14-16`、`db.py:21`、`orchestrator.py:18`、`metrics.py:46`）。

新增 `MAESTRO_HOME` 环境变量（exe 同级目录）作为默认根目录，自动创建 `%MAESTRO_HOME%/data/maestro.db` 与 `%MAESTRO_HOME%/outputs`，避免对 `sys._MEIPASS` 的写权限问题。

非 Windows 平台：实现空 stub，主窗口独立运行（PyWebView 单窗口）。

### 第 3 步：PyWebView 启动器 `src/maestro/launcher.py`

```python
def run() -> int:
    # 1) 启动后端（subprocess 模式，避免 PyInstaller 嵌进程与 Python 嵌 Chromium 抢 GIL）
    server_proc = subprocess.Popen([sys.executable, "-m", "maestro.server"],
                                    env={**os.environ, "MAESTRO_PORT": str(PORT),
                                         "MAESTRO_HOME": str(project_root())})
    # 2) 等服务就绪（轮 /api/healthz，30s 超时）
    wait_health()
    # 3) Windows：后台启动壁纸层（透明 PyWebView 窗口挂 WorkerW）
    if sys.platform == "win32":
        threading.Thread(target=install_wallpaper_layer, args=(f"http://127.0.0.1:{PORT}/",),
                         daemon=True).start()
    # 4) 主线程启 PyWebView（创建独立 Chrome 窗口打开主界面）
    webview.create_window("Maestro", f"http://127.0.0.1:{PORT}/", 
                         width=1400, height=900, min_size=(900, 600))
    webview.start()
    # 5) 主窗口关闭：结束壁纸层 + 终止服务
    server_proc.terminate()
    return 0
```

**关键决策**：后端用 subprocess 而非同进程 run——PyInstaller onefile 模式下 `python -m maestro.server` 走 `sys._MEIPASS` 的 module 查找路径与当前进程不同，必须另起进程才能稳定。同时双进程模型让浏览器崩溃不连带后端。

### 第 4 步：PyInstaller spec `packaging/maestro.spec`

```python
# -*- mode: python ; coding: utf-8 -*-
a = Analysis(
    ['src/maestro/launcher.py'],
    binaries=[],
    datas=[
        ('src/maestro', 'maestro'),                    # Python 包
        ('web', 'web'),                                 # 前端三件套
        ('wallpaper', 'wallpaper'),                     # 壁纸素材（裁剪后）
        ('configs', 'configs'),                         # 配置 + 工作流 + 技能
    ],
    hiddenimports=['uvicorn.logging', 'uvicorn.loops', 'uvicorn.loops.auto', 
                   'uvicorn.protocols', 'uvicorn.protocols.http', 
                   'uvicorn.protocols.http.auto', 'uvicorn.protocols.websockets',
                   'uvicorn.protocols.websockets.auto', 'watchfiles'],
    excludes=['tkinter', 'matplotlib', 'numpy', 'pandas', 'scipy',
              'pytest', 'pytest_asyncio', 'ruff', 'mypy'],
    # 重要：pydantic 配套 + pywebview 钩子由 PyInstaller 自动处理
)
pyz = PYZ(a.pure, a.zipped_data, cipher=None)
exe = EXE(pyz, a.scripts, [], exclude_binaries=True, name='Maestro',
          debug=False, strip=False, upx=True, console=False,  # 无控制台窗口
          icon='wallpaper/models/frieren/未标题-1.png')
coll = COLLECT(exe, a.binaries, a.zipfiles, a.datas, strip=False, upx=True,
               name='Maestro')
```

**onedir 模式**（一个 exe + 一个 _internal/ 目录）而不是 onefile：①启动快（无 50MB 临时解压）②用户能直接编辑 `_internal/configs/` 和 `data/maestro.db` 备份 ③失败好排查。

### 第 5 步：资源裁剪脚本 `packaging/prune_assets.py`

打包前自动执行，与 `.dockerignore` 对齐：
- 删除 `wallpaper/models/source/user_char_ref.psd`（5.6 MB，开发者源）
- 删除 `wallpaper/models/live2d/avatar/**/.*bak`、`model.*bak`、`*.motion3.json.bak`（所有 `.bak` 备份，共 ~6 MB）
- 删除 `web/pet_q_v2/_test/*.js`（12 个调试脚本，~50 KB）
- 删除 `web/pet_q/_old*`（备份，~200 KB）
- 删除 `ocwtest/`（如果 git 没排除干净）

结果：裁剪后产物从 ~110 MB 降到 ~50 MB。

### 第 6 步：打包脚本 `packaging/build.py`

```python
#!/usr/bin/env python3
"""本地打包入口：python packaging/build.py [--onefile]"""
import subprocess, sys
subprocess.check_call([sys.executable, "packaging/prune_assets.py"])
subprocess.check_call(["pyinstaller", "--clean", "--noconfirm", "packaging/maestro.spec"])
# 产物：dist/Maestro/Maestro.exe + dist/Maestro/_internal/
```

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| Wallpaper Engine / 第三方壁纸软件占用 WorkerW | desktop.py 检测到 `EnumWindows(WorkerW)` 已有子窗口时 fallback 到 PyWebView 独立窗口，不强抢 |
| PyWebView 在某些 Windows 版本（如 Win11 22H2）启动失败 | 加 try/except 退到 `webbrowser.open()`，最低保证可用 |
| 端口 8787 被占用 | 启动器扫 8787~8797，被占就递增；启动后向 `%APPDATA%/Maestro/port.txt` 写实际端口，前端读 location.origin 已支持 |
| 后端 subprocess 在子进程崩溃时静默挂掉 | launcher.py 单独线程 watch `server_proc.poll()`，死了自动重启一次，仍失败就弹窗报错 |
| PyInstaller 把测试也打进 exe | spec `excludes=['pytest', 'pytest_asyncio', 'ruff', 'mypy']` |
| 用户首次运行需要 GPU/驱动 | HTML 壁纸层只用 CSS transform + Canvas 2D（live2dcubismcore.min.js 已 WebGL 备选，但优先走 Canvas），不依赖 GPU |
| 体积超 60 MB | `prune_assets.py` 把 .bak/_test/PSD 源全裁（预计 -30 MB）；live2d 模型文件不大（< 5 MB）全保留 |

## 不在 v1 范围

- 自动更新（用 nssm 注册成 Windows 服务更稳）
- 多实例/多用户隔离
- 数字签名 / 防病毒免检（需要 code signing 证书）
- 安装包制作（NSIS / Inno Setup，超出本任务；用户双击 exe 即可启动）

## 验收标准

1. 干净的 Windows 11 机器上 `python packaging/build.py` 全程成功，产物在 `dist/Maestro/Maestro.exe` 大小 ≤ 60 MB
2. 双击 `Maestro.exe` → 5 秒内出现桌面壁纸层（芙莉莲背景）+ 主交互窗口（聊天框），无 Python 解释器/控制台弹出
3. 主窗口聊天框可发消息并收到 SSE 流式回复（依赖项：API key 已在 .env 或环境变量）
4. 关闭主窗口 → 壁纸层随服务退到后台；再次双击 → 直接拉起主窗口，服务已就绪秒开
5. 测试套件 `pytest tests/ -q` 仍 437 全绿（新增 1 个 packaging 测试）
